## 发现的问题（按严重程度）

### 🔴 P0 — 直接阻塞批量流程

**`batch_merge` 和 `merge_record` 没有注册到 MCP Server**

`server.py` 的 `register_tools()` 里，`data_merge` 模块只注册了三个工具：

```python
mcp.add_tool(data_merge.read_excel_data)
mcp.add_tool(data_merge.generate_barcode)
mcp.add_tool(data_merge.generate_qrcode)
```

`merge_record` 和 `batch_merge` 完全没有注册。这意味着 Agent 通过 MCP 无法触发批量合并，整个"Excel → 批量 CDR"的核心流程在 MCP 层是断的。Agent 能读 Excel，但不能批量跑模板替换。

**修复方式：** 在 `register_tools()` 加两行：
```python
mcp.add_tool(data_merge.merge_record)
mcp.add_tool(data_merge.batch_merge)
```

---

**`batch_merge` 执行后文档不关闭**

`data_merge.py` 的 `merge_record` 函数：打开模板 → 替换 → `SaveAs`，但没有调用 `doc.Close()`。71条记录跑完会有 71 个文档同时开着，CorelDRAW 必然崩溃。

---

### 🟠 P1 — 对 S05303 项目直接缺失

**没有 `list_templates` 工具**

设计文档里明确说"Agent 调用 `list_templates()` 工具返回模板配置"，但这个工具完全没有实现。Agent 当前无法知道有哪些模板可用，只能靠 prompt 里硬编码路径，这在真实部署中不可维护。

---

**Template Registry 里没有 S05303 对应的模板**

`template_registry.json` 里只有通用示例（门牌_200x80_红底白字、门牌_300x120_蓝底白字、导向标识_400x200_箭头），没有 S05303 这个公寓门牌项目的配置：
- 字体：Gotham Narrow Light
- 材质：304# 砂钢  
- 尺寸规则：2字符宽度 vs 3字符宽度
- 盲文珠位置
- 工程图标题栏字段

---

**没有尺寸变体规则**

S05303 的 .ai 文件里清楚标注了：`3A`（2位）宽度是 2"，`10A`（3位）宽度是 3"。但当前系统完全没有"字符数 → 页面宽度"的规则机制。Agent 必须自己猜，或者每次都要靠 prompt 描述。

需要在 template_registry.json 加 `size_variants` 字段，或者专门加一个 `get_size_variant` 工具。

---

**没有工程图装配能力**

这是与最终 PDF 产出之间最大的落差。你发的 `C260330LL01BP001.pdf` 是一张完整的工程图——不只是门牌设计，还有：标题栏（项目名、订单号、产品料号、设计人等）、1:1尺寸标注线、材料规格说明文字、第一视角投影符号。

当前项目只能输出门牌设计本体的 PDF，没有能力组装这套工程图框架。这需要：
1. 一个专用的工程图 CDR 模板（图框 + 标题栏）
2. 一个 `populate_title_block(fields)` 工具，按订单信息填标题栏
3. 或者通过 `merge_record` 把设计文件嵌入到工程图模板

### 🟡 P2 — 代码质量问题

**runner.py 里的模型名已过期**

```python
def _default_model(self) -> str:
    if self.provider == "anthropic":
        return "claude-sonnet-4-5-20250929"  # 旧版本
```

当前应该用 `claude-sonnet-4-6`。

---

**`export_pdf` 的 `color_profile` 参数是空参数**

```python
doc.PDFSettings.ColorMode = 1  # cdrPDFCMYK
```

`color_profile` 参数被接受了但完全没有被使用——ICC Profile 没有真正加载。对于要求 `ISO_Coated_v2` 的印刷交付，这个问题不容忽视。

---

**`check_missing_fonts` 的检测逻辑有问题**

通过"尝试用字体名创建一个新形状"来判断字体是否存在，这个方法不可靠：CorelDRAW 在字体缺失时通常会 fallback 而不是抛异常，会产生大量漏检。
