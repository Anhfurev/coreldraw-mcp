# 决策记录 2026-04-27

## 工具实现架构模式
- **选择**：所有 MCP 工具采用 `get_connection() → check connected → safe_call(lambda) → ToolResult` 统一模式
- **原因**：safe_call 已在 connection.py 实现完整的重连/重试/错误封装，工具层不应重复处理 COM 异常。lambda 包裹可确保重试时重新执行，避免闭包捕获过期状态。
- **影响**：所有 53 个工具函数遵循此模式，新工具必须保持一致
- **不可推翻**：是 — 这是与 connection.py 绑定的架构约定

## 工具模块组织
- **选择**：工具函数在模块文件中定义为普通函数（无 @mcp.tool() 装饰器），由 server.py 统一通过 mcp.add_tool() 注册
- **原因**：server.py 已有 add_tool 注册模式（feat-001 遗留），工具模块保持独立可测，不依赖 FastMCP 实例
- **影响**：tools/*.py 不导入 mcp/fastmcp，函数签名即工具接口契约

## COM 常量管理
- **选择**：COM 滤镜编号/DXF版本/单位等魔术数字定义为模块级大写常量或映射字典
- **原因**：CorelDRAW COM 类型库在 Python 环境下无法自动导入常量（需要 makepy 预先处理），直接使用整数是唯一方案
- **影响**：后续可通过 makepy 生成的类型存根替换为类型安全常量，当前模块级变量为替换点

## feat-002 完成判定
- **选择**：feat-002 passes 设为 true
- **原因**：所有 8 个模块 53 个工具函数已实现，server.py 导入链验证通过。工具覆盖文档管理、文字替换、PDF/DXF 导出、模板打开与内容替换等核心场景。
- **影响**：feat-003（端到端验证）和 feat-004（视觉预览）的前置依赖已满足，可并行推进。
